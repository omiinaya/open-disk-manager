## Evening Session - Model Configuration Fix

### Problem
Kimi K2.5 was working but Step-3.5-Flash and GLM-4.7 threw "context window too small (8192 tokens)" errors when set as default.

### Root Cause
The NVIDIA models were configured with `contextWindow: 8192` — but that's just the `maxTokens` (output limit), not the actual context window. OpenClaw requires minimum 16K context for primary models.

### Solution
Updated model specs from actual sources (OpenRouter shows real specs):
- **Kimi K2.5**: 262K context (was already ~256K)
- **Step-3.5-Flash**: 256K context (was 8K!)
- **GLM-4.7**: 203K context (was 8K!)

### Key Distinction Learned
- `contextWindow`: Total tokens model can process (input + output + system prompt + memory + tools)
- `maxTokens`: Just the output limit
- These are completely separate — never set them equal

### Skill Created
Made `nvidia-model-config` skill to document this pattern. Stored at `/root/.openclaw/workspace/skills/nvidia-model-config.skill`

### Config Applied
Two patches via `gateway config.patch`:
1. Initial fix to 32K/128K (may still have been conservative)
2. Final fix to actual OpenRouter specs: 256K, 262K, 203K

Gateway restarted successfully both times. All three models now exceed 16K minimum and can be set as default.
